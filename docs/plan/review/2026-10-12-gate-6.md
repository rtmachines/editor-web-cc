## Decisions for the seventh (final) reconciliation (author, 2026-10-12)

| M1 | `DefineUdt` is the explicit exception: a member whose TypeExpr resolves to a type that is not on the platform reports `E-PLT-006 MemberTypeNotOnPlatform { member, platform }`, because the member name is the useful detail. Every other TypeExpr consumer reports `E-PLT-013`. ADR-0017:49, domain-model 2.1 and I6 state the exception |
| M2 | A command parses every TypeExpr it carries, collects the needed derived-type keys, sorts them in the fixed order (struct name, `STRING`, `WSTRING`, `ARRAY`) and takes all class-2 advisory locks in that order before the first `plc_type` insert. domain-model 5.1 (EnsureDerivedType note), data-model 1.4 and the DefineUdt/AddParameter/UpdateParameterDefinition/RebindTypeRevision rows, ADR-0017 |
| M3 | New `AppError::TaskFailed { stage }` owns `E-WEB-011` (500, message "The operation {stage} did not complete. Try again. Reference: {request_id}."). `JoinError` from `spawn_blocking` maps to it. reliability 2.4 and 1.1/1.2; `E-WEB-010` stays for a panic caught by `CatchPanicLayer` |
| M4 | In read-only mode `Login` keeps T1 (`login_attempt` insert) and the failed-login `security_event` aggregation. These writes are small and are inside the reserved margin of 7.8. A24 text and the domain-model 8 copy, data-model Login row, reliability 7.8, ADR-0014 |
| M5 | A concurrent index on an audit object is a runbook procedure, not a migration: the operator runs `GRANT CREATE`, `SET ROLE audit_owner`, `CREATE INDEX CONCURRENTLY`, `RESET ROLE`, `REVOKE CREATE` as `recipe_migrator` in one psql session, then records the index in the next migration with `CREATE INDEX IF NOT EXISTS`. data-model 5.1 and 8, reliability 5 and 7.10 |
| M6 | 64-bit time types: the stored and hashed value is the decimal text of the count, so both signed and unsigned 64-bit ranges fit. The base-unit table gives these ranges per type and platform instead of `i64` |
