The plan uses three OpenSpec changes. Each change gets its own branch and its own pull request. Each change follows the cycle of `CLAUDE.md` "Workflow".

| Change | Scope | Implementer | Depends on |
|---|---|---|---|
| A `review-code-fixes-2` | Code, tests, and comments with no design decision | Sonnet, Haiku for `[mechanical]` tasks | None |

| C `review-deploy-fixes-2` | `deploy/`, the shell tests, and `docs/ops/runbook.md` | Codex `gpt-6.2-sol` | None |

- Opus writes each proposal and each design, and reviews each change. Codex `gpt-6.2-astra` at the effort `high` reviews each change in parallel.
- Changes A and C touch different files. They can run in parallel.
- Change B starts after changes A and C are merged.
