## 4. WP1: change `runtime-safety-round-1`

### 4.1 D7-1: no password in the log of the init script (HIGH)

- ADR (new, amends ADR-0031): the init script turns off `log_min_duration_statement` before the first statement with a password.
- Documents: the SQL block of `data-model.md` §5.1 gets the line `SET log_min_duration_statement = -1;`. ADR-0031 gets the note "Amended by ADR-0123".
- Tasks:
  1. Failing test (Sonnet, `recipe-db`): `tests/storage/grants/init_script.rs` asserts that the three `SET` lines come before the first `CREATE ROLE` of `01-roles.sh`.
  2. Failing test (Sonnet, `recipe-db`): a testcontainers test runs `01-roles.sh` on a server with `log_min_duration_statement=0` and asserts that the server log holds no `PASSWORD '`.
  3. Fix (Codex, `deploy/`): add `SET log_min_duration_statement = -1;` after line 71 of `deploy/db/initdb/01-roles.sh`.
  4. Runbook (Haiku, `docs/ops/runbook.md`): add a step for an existing installation. The operator searches the log of `db` for `PASSWORD '` and rotates each password that the log shows.
- Note: the fix changes no role attribute and no membership, so ADR-0103 (m) needs no forward step. The fix acts only on a new volume. The runbook step covers an existing volume.

### 4.2 D4-1: no open transaction goes back to the pool (MEDIUM)

- ADR (new, amends ADR-0058 (m)): the pool closes a released connection that holds an open transaction.
- Documents: `reliability.md` §7.5 names the hook. `overview.md` §9 A15 stays unchanged (Q-A (1)).
- Tasks:
  1. Failing test (Sonnet, `recipe-db`): with a pool of size 1, send a raw `BEGIN` on an acquired connection and release it. Acquire the connection again and assert that the server shows no open transaction. Today the test fails.
  2. Fix (Sonnet, `recipe-db`): add `after_release` in `pool_options` (`crates/recipe-db/src/database.rs:187`). The hook runs `SELECT transaction_timestamp() < statement_timestamp()` and returns `Ok(false)` on `true` or on an error. Do not use `Connection::is_in_transaction()`, because it reads the depth of sqlx, which is 0 in this case.
  3. Test (Sonnet, `recipe-db`): the hook adds no failure to the existing storage suite, and a normal release keeps the connection.
- Risk: the hook adds one round trip per release. `return_to_pool` runs in a spawned task, so the request does not wait for it.

### 4.3 D2-1: the end of an accept loop stops the server (MEDIUM)

- ADR (new, amends ADR-0090 (b)): the server races the stop signal against the end of each accept loop. When a loop ends first, the server writes one `ERROR` line and stops with exit code 70 (option Q-C (1)).
- Documents: `reliability.md` §2.4 rule 6 names the join of an accept loop and the join of the watchdog thread as places that catch a panic. `.claude/rules/rust.md` gets the same list.
- Spec delta (`operations`): a new scenario "An accept loop ends before the signal": the process exits with code 70.
- Tasks:
  1. Failing test (Sonnet, `recipe-server`): a test ends the public accept loop through a test hook. It asserts that the server returns an error before a signal.
  2. Fix (Sonnet, `recipe-server`): `Server::wait_for_signal` (`serve/server.rs:170`) also waits for the end of each accept-loop task.
  3. Docs (Haiku): the rule-6 list in `reliability.md` §2.4 and `.claude/rules/rust.md`.
