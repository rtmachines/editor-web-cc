# Tasks

Each task is for one agent. The mark after the scope names the agent: `[sonnet]` (Sonnet, effort high) or `[mechanical]` (Haiku). Every task of this change writes Rust code or tests, so every task is `[sonnet]`. The propose step already wrote ADR-0137 and the document edits, so no task is `[mechanical]`.

The tasks run one after the other in their order. Each red step mutates `crates/recipe-domain/src/recipe/value/leaf.rs` or `check.rs`, so two tasks do not run in parallel. Tasks 1.2 and 1.3 come before task 1.4, because the fix of D1 breaks the generator and the XSS tests that they change. Thus `cargo test --workspace` passes after each task.

A task with a fix writes its tests first, runs them, and sees them fail. Then it applies the fix. A pinning test shows its red step on a temporary mutation of the code under test. Before the mutation, the agent copies the file to the scratch directory. The agent runs the test and sees it fail. Then it reverts the mutation and runs `cmp <file> <copy>`. The report shows both test runs and the empty output of `cmp`. A wrong expected value in the test is not a red step.

The review record `docs/plan/review/2026-11-06-plc-type-review.md` gives the input of each finding. A test file that would pass 800 lines gets a sibling test file. After each task, the agent runs the three commands of `openspec/config.yaml` section `apply`.
