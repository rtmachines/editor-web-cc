# Tasks

Each task is for one agent. The mark after the scope names the agent: `[sonnet]` (Sonnet, effort high) or `[mechanical]` (Haiku). Every task of this change writes tests, so every task is `[sonnet]`. The propose step already wrote ADR-0138 and the document edits, so no task is `[mechanical]`.

The tasks run one after the other in their order. Tasks 1.1 to 1.4 apply the mutation M1 of `design.md` D2 to one file, so two tasks do not run in parallel. No task changes production code. Thus `cargo test --workspace` passes after each task.

Each task writes pinning tests with the shape of `design.md` D1 and the body of D3. A pinning test shows its red step on a temporary mutation of the code under test. Before the mutation, the agent copies the file to the scratch directory. The agent runs the new test on the mutation and sees it fail. Then it reverts the mutation and runs `cmp <file> <copy>`. The report shows both test runs and the empty output of `cmp`. A wrong expected value in the test is not a red step.

The review record `docs/plan/review/2026-11-06-plc-type-review.md` gives the input of finding #11. Each new test name starts with the prefix of the other tests of its file, so the filter of the check finds it. A test file that would pass 800 lines gets a sibling test file. After each task, the agent runs the three commands of `openspec/config.yaml` section `apply`.
