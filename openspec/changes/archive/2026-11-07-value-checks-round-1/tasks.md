# Tasks

Each task is for one agent. The mark after the scope names the agent: `[sonnet]` (Sonnet, effort high) or `[mechanical]` (Haiku). Every task of this change writes Rust code or tests, so every task is `[sonnet]`. The tasks run one after the other in their order. Several tasks write into `recipe/limit/parse/tests.rs` and `recipe/value/leaf/tests.rs`, so two tasks do not run in parallel.

A task with a fix writes its tests first, runs them, and sees them fail. Then it applies the fix. A pinning test shows its red step on a temporary mutation of the code under test, a plausible bug. The agent sees the test fail, reverts the mutation, and reports both runs. A wrong expected value in the test is not a red step.

The proving tests of the review are the source of the cases (`design.md` D5). A test file that would pass 800 lines gets a sibling test file. After each task, the agent runs the three commands of `openspec/config.yaml` section `apply`.
