# Tasks

Each task is for one agent. The mark after the scope names the agent: `[sonnet]` (Sonnet, effort high) or `[mechanical]` (Haiku). No task runs on Codex now (`design.md` D12). Each task of groups 1 to 9 first writes a failing test (RED) and runs it. Then it writes the change that makes the test pass (GREEN). The RED of a doc task is a check that finds the old text. Group 10 runs the final checks only.

A pgtools suite runs inside the `recipe-pgtools` image, as `deploy/ci/pgtools.sh` does. Build the image first with `docker compose -f deploy/compose.yaml -f deploy/compose.build.yaml build backup`. The storage tests and the pgtools suites need Docker. A run on the workstation needs the approval of the user, else it runs in CI.

## Run order

1. Groups 1, 2, 3, and 8 can start in parallel. Inside a group, the tasks run in their order.
2. Tasks 1.3, 1.4, and 1.5 land in one push. The first start of the job `compose` needs the mount of task 1.4. The job `upgrade` needs task 1.5.
3. The edits of `deploy/pgtools/Dockerfile` run one after the other, in the order 2.1, 2.2, 3.2, 6.1. Task 3.2 therefore starts after task 2.2.
4. Task 3.3 starts after tasks 2.3, 3.1, and 3.2. Tasks 2.3 and 3.3 both edit `tests/deploy_values/files.rs`, so they never run at the same time.
5. Group 4 starts after tasks 1.5, 2.2, and 3.2.
6. Group 5 starts after group 1. Tasks 5.1 and 5.2 land in one push, because the job `compose` needs both. Task 5.3 also waits for task 4.1.
7. Tasks 6.1 and 6.2 start after task 3.2. Tasks 6.3 and 6.4 start after task 5.2. Tasks 6.1 and 6.3 land in one push, because the job `upgrade` needs both.
8. The tasks that edit `docs/ops/runbook.md` or `CHANGELOG.md` run one after the other.
9. Group 7 starts after groups 4, 5, and 6. Group 9 starts after group 7.
10. At most two cargo agents run at the same time.
11. Group 11 follows ADR-0104. Task 11.2 runs before task 11.3. Both land in one push, because the unit test pins the form of `upgrade.sh`. Group 10 starts after group 11.
12. Group 12 follows ADR-0105. Task 12.1 is done. Tasks 12.2 and 12.3 edit `bin/restore-volume`, and tasks 12.4 and 12.5 edit `lib/wal-identity.sh`, so each pair runs in its order.
13. Task 12.7 runs before tasks 12.8 and 12.9. Tasks 12.7, 12.8, and 12.9 land in one push, because the test of task 12.7 compares the runbook with `upgrade.sh`.
14. Tasks 12.8, 12.10, and 12.11 edit `deploy/ci/upgrade.sh`, so they run one after the other. Task 12.9 follows item 8 of this list.
15. Group 10 runs again after group 12. Task 10.7 is the gate of the change.
